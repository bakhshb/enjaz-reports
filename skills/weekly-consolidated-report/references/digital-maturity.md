# Digital-experience model

All digital PowerPoint tables, including every detail table and challenge table, must use native RTL direction. Preserve the review JSON's PDF field order (`أساس التقييم | الإنجاز | المهمة | م`); map those values into the corresponding RTL table columns without changing the JSON schema. Numbering/codes appear at the right, and Latin task codes retain LTR text direction inside the RTL table: each code is written as its own run tagged `en-US` (PowerPoint lays out Arabic-tagged runs right-to-left and does not reliably honour bidi control characters). Validate direction independently of paragraph alignment.

Use this reference only after the user chooses **التقرير الموحد مع نضج التجربة الرقمية**. The added summary follows the transactions summary and precedes the detail divider. The divider's «تفاصيل مؤشر نضج التجربة الرقمية» button opens the populated indicator-detail slides after the task and Suhail details; the detail data must not appear only in the summary. The current model remains separate.

## Source contract: the landscape PDF

The current digital-maturity PDF is a required fourth input and arrives as the landscape («horizontal») export. It is a **data source only**; its layout, page breaks and page count are never reproduced.

- **Page one** holds the four perspective percentages (each card's headline value is the percentage in its largest type; a smaller weekly-change line under it is ignored), one sector bar row per agency/center (a gray bar with the note inside the label's parentheses — read in either logical or mirrored order — marks a sector that is not assessed separately), and the notes table (`# | المنظور | …`, titled «التحديات (آخر تحديث: …)» in the source).
- **Every later page belongs to one sector.** A sector may span several consecutive pages titled «القطاع (1/3)», «القطاع (2/3)», …; a continued section heading on a later page reads «المنظور: 15% (تتمة)»; a sector's challenges table («التحديات» or «أبرز التحديثات») may appear on any of its pages. All of these are **source pagination artifacts**. The unit of data is the sector, not the page.
- Pages without a «(k/n)» suffix are single-page sectors. Sectors keep their source order.
- The committed sample `tests/fixtures/digital-maturity-horizontal.pdf` is the approved source layout (16 pages: summary plus 3+2+1+3+6 sector pages). The approved **output** is `assets/weekly-report-digital-reference.pdf`, the user-approved report of 5 November 2026 exported from PowerPoint: one sector per contiguous run of slides, output-only «(k/n)», «(تتمة)» at the top of a continuation, then «أبرز التحديثات» and «التحديات» once at the end of the sector (an empty one omitted), and a single «أبرز التحديثات» table on the summary slide. Compare a generated report with the reference for design, never for values.

## Updates and challenges (رقمي)

The source gives each sector one notes table («أبرز التحديثات» or «التحديات») and page one a single «التحديات» table. Its title does not decide the output. During review, the agent:

1. **Classifies** every source note by its content: progress, a completed step, an expectation or work under way → `updates` (أبرز التحديثات / التحديث); a delay, an obstacle, a dependency, a missing decision or no response → `challenges` (التحديات / التحدي). A note that mixes both is split into one update and one challenge. Every source note must land in at least one list; none is dropped.
2. **Rewrites** each item in formal Arabic government register, preferably as «عنوان قصير: النص» (e.g. «تأخر التجاوب: …», «توحيد ملكية المحتوى: …»). Keep every percentage, count, date and named entity (منصة، وكالة، جهة). **Remove task codes** (`INF-02`, `S-02`, `CS-52`, `INF-05..07`) and say what they refer to in words (e.g. «أربعة متطلبات»); keep dates such as «4 نوفمبر 2026» or «28 أكتوبر». Add no fact that is not in the PDF. The builder rejects any note that still carries a task code.
3. Leaves a list empty when the sector has nothing of that kind; its table is then **omitted**, not shown empty.

The summary slide's table is titled **«أبرز التحديثات»** with the header `# | المنظور | التحديث` (1–4 rows from page one, `updates` key), rewritten under the same rules. A row whose text spans two points is written as two lines; each line renders as a native bullet inside the cell.

`scripts/digital_maturity.py` reads the landscape pages, restores logical Arabic from the visual text layer (Latin codes, digits, percentages and brackets included), and folds each sector's pages into one record set. The JSON keys are `source_pdf_sha256`, `source_date_hijri`, `metrics` (`experience`, `satisfaction`, `complaints`, `tools`), `sectors` (name, four metrics, optional note), summary `source_updates` (page one's notes as read, perspective and text; evidence only), `updates` (the summary table rows; drafted as a copy of `source_updates` and rewritten during review), `detail_sectors` (one entry per sector: `title` without suffix, `source_pages`, `cards`, four-column `rows` including section headings but no «(تتمة)», `source_notes` — every note from all of the sector's pages with its source table title, evidence only — and the reviewer-filled `updates` and `challenges` lists) and `reviewed`. The extractor begins with `reviewed: false` and empty `updates`/`challenges` per sector because the PDF text layer can still reverse glyphs, lose characters as `(cid:…)`, or wrap codes, and because classification and rewriting are review work. Compare every field with the rendered source pages, correct the JSON, classify and rewrite the notes (see «Updates and challenges» above), then set `reviewed` to `true`. The builder rejects a sector whose source notes were not classified, a note with a task code, and the retired keys `challenge_title`, `challenge_header` and summary `challenges`. If any row or note is illegible or ambiguous, stop and request a clearer source. Do not infer runtime data from master examples.

The master's detail slides are **design patterns only**: the first one supplies the title strip, the header row, one section-heading row per perspective (its fill color), the body row, the four cards and the challenge table. Never carry sample percentages, rows, or challenge prose from the PowerPoint master into a generated report. The master summary still contains sample values that differ from the supplied PDF; the PDF controls runtime values. Preserve the master's fixed «آلية الاحتساب» note between the four indicators and sector chart, including its wording and emphasis; the source's own «أساس الاحتساب» line is not extracted.

## Output pagination (portrait slides)

The builder re-flows every sector with the same continuous-flow rules used for task and Suhail details:

- One sector starts on a fresh detail slide; its records fill the slide down to the footer clearance. The number of digital detail slides follows the data, not the number of source pages.
- Records are never split, and a section heading never ends a slide. When a section continues on the next slide, the continuation starts with the same heading plus «(تتمة)» (generated from the output pagination, never copied from the source).
- A sector that needs more than one slide titles them «القطاع (1/n)» … «القطاع (n/n)» where *n* is the number of **output** slides; a single-slide sector has no suffix. The four cards repeat with identical values on every slide of the sector.
- The sector's «أبرز التحديثات / التحديث» table, then its «التحديات / التحدي» table, appear **once**, directly below the last records of the sector, each after the small approved gap. A table whose list is empty is omitted. If they cannot fit under the last record, the trailing record moves with them to the next slide; a slide never holds only these tables.
- The task/indicator column keeps the master's fixed header; the source's «المؤشر» header is not transferred.
- Surplus master detail slides are removed; the remaining block stays contiguous after the Suhail details and before the thank-you slide, and the divider button targets its first slide.

The summary slide has room for up to five sector rows and four update rows; if a future source exceeds that space, stop for a revised layout rather than silently drop records or shrink the 11 pt table font. The four perspective values and sector percentages are independent rates, not portions that must sum to 100. Preserve every number as shown. A missing perspective for one sector stays blank. A sector marked with a note has a labeled gray bar and no invented percentages. Keep the summary updates' perspectives in source order.
