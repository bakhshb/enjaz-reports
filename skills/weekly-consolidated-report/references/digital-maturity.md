# Digital-experience model

All digital PowerPoint tables, including the six detail tables and their challenge tables, must use native RTL direction. Preserve the review JSON's PDF field order; map those values into the corresponding RTL table columns without changing the JSON schema. Numbering/codes appear at the right, and Latin task codes retain LTR text direction inside the RTL table. Validate direction independently of paragraph alignment.

Use this reference only after the user chooses **التقرير الموحد مع نضج التجربة الرقمية**. The added summary follows the transactions summary and precedes the detail divider. The divider's «تفاصيل مؤشر نضج التجربة الرقمية» button opens six populated indicator-detail slides after the task and Suhail details; the detail data must not appear only in the summary. The current model remains separate.

The current digital-maturity PDF is a required fourth input. Read and visually review **page one**, which contains the four perspective percentages, one sector row per agency/center, and the challenges table. PDF pages **two through seven** supply the six detail slides: each page's title, four perspective cards, table rows and challenges. Never carry sample percentages, rows, or challenge prose from the PowerPoint master into a generated report. The master summary still contains sample values that differ from the supplied PDF; the PDF controls runtime values. Preserve the master's fixed «آلية الاحتساب» note between the four indicators and sector chart, including its wording and emphasis; it explains the calculation method and is not a value to extract from the PDF.

Run `scripts/digital_maturity.py` to extract a JSON review file. Its keys are `source_pdf_sha256`, `source_date_hijri`, `metrics` (`experience`, `satisfaction`, `complaints`, `tools`), `sectors` (name, four metrics, optional note), summary `challenges` (perspective and text), six `detail_pages` (PDF page, title, cards, four-column rows including section headings, challenge text), and `reviewed`. The extractor begins with `reviewed: false` because Arabic PDF text can reverse glyphs, dates, percentages, Latin task codes, or ligatures. Compare all seven rendered PDF pages with every field, correct the JSON, then set it to `true`. If any row or challenge is illegible or ambiguous, stop and request a clearer source. Do not infer runtime data from master examples.

The four perspective values and sector percentages are independent rates, not portions that must sum to 100. Preserve every number as shown. A missing perspective for one sector stays blank. A sector marked `قيد الدراسة` has a labeled gray bar and no invented percentages. Keep the challenge wording and perspective in source order. The approved slide has room for up to five sector rows and four challenge rows; if a future source exceeds that space, stop for a revised layout rather than silently drop records or shrink the 11 pt table font.
